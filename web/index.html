How it works

The interface you are using is a plain web page. When you press a Run button it sends your input to a small Java program running on your own computer (the back end, started with run.sh or run.bat). The Java program runs the algorithm and sends back four things: the result, every step it took, how many basic operations it performed, and how long it ran. Nothing leaves your machine and no outside service is used.

Everything is written from scratch

All sorting, searching and recursive algorithms are hand-written. So are the data structures they rely on: a dynamic array, an array-backed stack, a circular-array queue, a singly linked list, a binary search tree, a binary min-heap and a hash table with chaining. The Java code never imports java.util collections or calls Arrays.sort or Collections.sort. Even the JSON output, the random number generator and the input parser are our own.

What gets counted

Comparisons
Every time two elements are compared (or a base-case test runs, in recursion).
Swaps
Every exchange of two elements.
Writes
Single element writes: shifts in insertion sort, merges into the array, counting-sort placements, Hanoi disk moves.
Arithmetic
Additions, multiplications and divisions inside recursive algorithms.
Recursive calls
Every call of a recursive function, including base cases. Max depth is the deepest the call stack got.
Total operations
The sum of all of the above. This number depends only on the algorithm and the input, so it is the fair way to compare growth rates.

How running time is measured

Recording steps is slow, so each request runs the algorithm twice: once with step recording on, to collect the replay, and then five more times with recording off. The time shown is the median of those five silent runs, measured with System.nanoTime(). Times vary from run to run because of the Java JIT compiler and whatever else your computer is doing. Operation counts do not vary.

Reading the complexity analysis

The analysis page runs algorithms on growing inputs and estimates their growth rate in two ways. The growth exponent is the slope of log(operations) against log(n): about 1 for O(n), about 1.1 for O(n log n), about 2 for O(n²). The best-fit model is the function f(n) for which operations ÷ f(n) stays most constant across your sizes. Try quick sort on random and then on already-sorted input to see the worst case appear.
